# AWS demo environment

The demo uses the newer AWS project's assigned Sydney region (`ap-southeast-2`). Its regional limitation is specific to that account; do not assume all AWS accounts have that restriction. The Terraform configuration in `terraform/aws-ha` provisions three small EC2 servers in separate default-VPC availability zones, encrypted gp3 root volumes, and a network load balancer. Ansible installs Docker, Helm and three k3s servers with an embedded etcd quorum; k3s uses its bundled containerd runtime. It also installs the maintained F5 NGINX Ingress Controller with Helm. The load balancer forwards to NGINX's NodePort 30081, which routes to the app. CloudNativePG provides one PostgreSQL primary and two replicas on node-local persistent volumes, with synchronous replication and failover quorum. Prometheus, Grafana, node-exporter and metrics-server run inside the cluster.

This is a demonstration, not a production service: HTTP is unencrypted, the app has no login, network access is restricted to specified operator IP addresses, and there are no automated off-node PostgreSQL backups. IP addresses may be shared by other users of a VPN or carrier network and can change. Do not use the demo for confidential data. Replication does not replace backups. Losing a control-plane quorum or multiple database replicas can interrupt service or threaten data. The GitHub deployment runner runs on one node, so deployment automation is unavailable while that node is down even if the application remains available.

On 1 November 2026, a browser test created and edited a temporary task through the load balancer. Deleting the database primary pod caused a standby promotion; the cluster returned to three healthy instances and the task remained. During that test, 20 health probes succeeded and one failed. Stopping the EC2 node hosting the new primary caused a longer interruption: 11 health probes succeeded and seven failed during a 110-second observation, with the first success about 65 seconds after the stop request. The test node was restarted, and the test task was subsequently deleted through the browser. These results describe individual tests, not a guaranteed recovery time or uninterrupted availability.

Later on 1 November, the servers were stopped and the load balancer removed, then both were restored to verify the updated presentation-aligned stack. Ansible installed Docker and Helm and deployed NGINX ingress; the three database replicas recovered, all load-balancer targets became healthy, and browser create, edit and delete actions passed through NGINX. CPU and memory HPA metrics were available on AWS. CPU and memory scale-out were tested on the local cluster, not on AWS.

AWS charges for running instances, public IPv4 addresses, load balancer, storage, and data transfer consume the account's credits. Stopping instances does not remove load-balancer, storage, and other non-compute charges. The free plan ends when its credits are depleted or its period expires; monitor AWS billing and stop the environment when it is no longer needed.

Prometheus evaluates alerts for app unavailability and high process memory. Alertmanager sends firing and resolved notifications through the `stratego-alerts` SNS topic to the confirmed email subscriber. The SNS publisher role is limited to that topic and assigned to node 1; Alertmanager is pinned there and uses host networking for IMDSv2. Alertmanager uses ephemeral notification state and is a single replica: a node outage or a paused cluster can interrupt notification delivery, and restarts can cause repeat notifications. An alert about an entirely stopped cluster cannot be sent by that same cluster. The SNS topic and role are managed in the separate `terraform/aws-alerts` state; the email subscription was created separately and requires email confirmation. The app HPA uses both CPU and memory utilization.

AWS autoscaling verification on 1 November 2026 used an internal load generator and a tunnel through NGINX. Under CPU load, the deployment reached five ready replicas. One 100-second tunnel load run completed 635 requests without errors, and a second 90-second run completed 1,607 requests without errors; these do not count requests from the internal generator and are not a capacity benchmark. A separate memory test established an idle two-pod baseline, temporarily lowered the memory target from 80% to 25%, and observed three ready replicas while CPU was 3% and memory was 50%; the target was restored. An Alertmanager test email was confirmed received, and a separate temporary Prometheus rule reached Alertmanager and SNS without reported publish failures. The test rule was removed afterward.

## Local operator files

Terraform state is local to `terraform/aws-ha/terraform.tfstate` and `terraform/aws-alerts/terraform.tfstate`; both must be protected and backed up securely. The untracked `data/aws/` directory contains the SSH private key, join token, kubeconfig, deployment-runner credentials, and Grafana password. Never commit or share these files. Losing the SSH key or Terraform state complicates recovery and management. The CloudNativePG database was initialized separately; this does not migrate tasks from the local cluster.

The kubeconfig on this Mac reaches the API over an SSH tunnel to node 1. The kubeconfig and inventory in `data/aws/` are machine-specific. Regenerate the inventory if public instance IP addresses change. Grafana is internal to the cluster and its admin password is in `data/aws/grafana-password`.

Use the AWS CLI profile configured for the correct account. For example, `aws sts get-caller-identity --profile stratego-new` confirms the identity; `AWS_PROFILE=stratego-terraform terraform -chdir=terraform/aws-ha output` shows infrastructure details. Review any Terraform plan before applying it. Node replacement is blocked with `prevent_destroy`; the Ubuntu image is pinned, and the public-IP setting is ignored after creation to avoid replacement when instances are stopped. The GitHub Actions runner uses a Kubernetes service account scoped to the named app resources and the `stratego-aws` context. Trusted workflow code can exercise that deployment access.

## Pausing and resuming

The app can be paused by disabling the repository variable `STRATEGO_DEPLOY_ENABLED`, stopping the three tagged EC2 instances, and using a reviewed targeted Terraform plan to remove only the load balancer and listener. Keep the instances, root disks, database data, Terraform state and `data/aws/` files. The site and deployment runner will be unavailable. EBS storage continues to incur charges. Removing the load balancer changes the site URL when it is recreated.

To resume, verify the account and operator IP CIDRs, then review a Terraform plan carefully: **no instance or database volume should be replaced**. Start the same three instances and wait for them to run. Regenerate the inventory with `python3 scripts/aws_inventory.py --profile stratego-new --region ap-southeast-2 --account YOUR_ACCOUNT_ID --key data/aws/stratego-aws > data/aws/inventory.json`; public IPs change after stop/start. Run `STRATEGO_K3S_TOKEN="$(cat data/aws/k3s-token)" ansible-playbook -i data/aws/inventory.json ansible/aws-ha.yml`. Apply the reviewed plan to restore the load balancer and update its target port to the ingress NodePort. Recreate the SSH API tunnel to node 1's new public IP; use the admin kubeconfig to apply `k8s/aws/deployer-rbac.yaml` and bootstrap the ingress and app overlay before re-enabling deployment. Apply the updated monitoring config separately and restart Prometheus so it loads the rules. Verify all cluster nodes, database replicas, ingress targets and app health before setting `STRATEGO_DEPLOY_ENABLED=true`.

To remove this environment when it is no longer required, first back up any data and confirm that the correct Terraform state and account are selected. The node `prevent_destroy` protection must be intentionally removed before a full destroy. Destroying the EC2 instances deletes their root volumes, including node-local database data. Remove the runner from GitHub when decommissioning. Do not destroy the nodes if data must be retained.
